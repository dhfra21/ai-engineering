## Problems so far (details in postmortem.md)

- Two Windows bugs were fixed: the mock test assumed `data/labels/` existed, and printing crashed on the cp1252 console encoding.

## Update (later on 2026-10-06)

- **The labels were wrong more often than the judge.** Judge v1's dev disagreements exposed label errors: "lists every customer / each category" over inner joins, and one missing output column. New guide rule 3.12 was applied by a sweep over all 161 items, test included and before any judge run on test. 13 labels were changed in total (`data/labels/overrides.jsonl`, each with its reason). Golden set: **85 good, 76 bad**, now frozen.
- **Judge on dev, against the final labels:** v1 53/60 (88.3%, κ 0.768, bad caught 27/33); v2 53/60 (88.3%, κ 0.765, bad caught 29/33). It's a tie, and we chose v2 for recall. Remaining misses: a clause-by-clause SQL restatement passed as clear (c-q140), and "for each product" read as "lists every product" (c-q127).
- **Caveat:** these label fixes were prompted by the judge, which nudges dev agreement up. The test-split score is the number that counts.
